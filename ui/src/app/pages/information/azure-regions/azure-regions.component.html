Key concepts

Use region pairs and availability zones as inputs to a service-specific resiliency design.

Paired and nonpaired regions

Some Azure services use region pairs for geo-replication and recovery sequencing. Of the {{ totalRegionCount }} regions listed here, {{ pairedRegionCount }} have a recorded pair and {{ totalRegionCount - pairedRegionCount }} are nonpaired. A region pair does not automatically configure failover or disaster recovery.

  • Some services use pairs for geo-replication and recovery sequencing
  • Planned platform updates are generally sequenced across paired regions
  • Most pairs remain in one geography, but documented exceptions exist

Availability zones

Availability zones are separated groups of datacenters within a region, with independent power, cooling, and networking. Some zones contain one datacenter and others contain more than one. {{ availabilityZoneRegionCount }} of the regions listed here currently indicate AZ support.

  • Independent infrastructure helps isolate zone-level failures
  • Microsoft targets less than approximately 2 ms round-trip network latency between zones; observed workload latency varies
  • Configuration options and availability SLAs vary by Azure service

Frequently asked questions

Helpful context when planning region-specific deployments.

What defines an Azure region?
Azure regions are sets of datacenters connected through a dedicated low-latency network. They are grouped into geographies for data residency and compliance. Availability zones, where supported, provide physically separated groups of datacenters within a region.
How do paired and nonpaired regions work?
Microsoft associates some regions as pairs, and a small number of Azure services use those pairs for geo-replication, geo-redundancy, or recovery sequencing. Many newer regions are nonpaired and use availability zones as their primary in-region resiliency mechanism. Whether a region is paired or not, you must design and test a service-specific high availability and disaster recovery plan.
